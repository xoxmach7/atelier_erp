# Sheber Mobile MVP — продуктовая логика экранов ролей

## Общая логика приложения

Sheber Mobile — мобильное приложение для управления заказами ателье.

Главная бизнес-цепочка:

клиент → заказ → замер → выбор тканей/тюля → КП/расчёт → согласование → материалы → пошив → установка → фотоотчёт → АВР → остаток оплаты → завершение заказа.

Главный принцип интерфейса:

роль → список заказов → цветной статус → открыть заказ → выполнить действие.

Не делать сложные таблицы, web-dashboard, перегруженные карточки и лишние объяснения. Мобильный интерфейс должен быть простым: список заказов, цветной индикатор, понятное действие.

## 1. Авторизация

Экран авторизации:

- позже будет добавлен логотип;
- название: Sheber;
- подпись: Единая база;
- поля:
  - телефон/email;
  - пароль;
- кнопка: Вход;
- demo-вход можно оставить для разработки.

---

## 2. Админ / владелец

Админ/владелец — главный пользователь приложения.

Он должен видеть:

- сколько заказов выполнено;
- сколько заказов в работе;
- какие заказы требуют внимания;
- какие просрочены;
- какие ожидают оплату;
- какие материалы на исходе;
- какие заказы можно завершить;
- все заказы и их текущий этап.

Dashboard должен быть простым, но полезным.

На dashboard должны быть переключатели:

- Прибыль;
- Выручка;
- Расходы.

График должен показывать динамику вверх/вниз по выбранному показателю. Если реальных финансовых данных пока нет, не выдумывать суммы — показывать аккуратный placeholder или 0.

Админ также может:

- видеть все заказы;
- смотреть, на каком этапе каждый заказ;
- добавлять новый заказ;
- быстро переключаться и смотреть рабочие экраны других ролей.

---

## 3. Дизайнер / замерщик

Дизайнер/замерщик должен видеть все заказы, которые относятся к его рабочему процессу.

Важно: дизайнера внутри заказа выбирать не нужно на первом этапе.

Дизайнер может:

- видеть заказы;
- создавать новые заказы;
- редактировать заказ;
- создавать и редактировать замеры;
- выбирать ткани и тюль;
- указывать метраж;
- вносить данные комнат/окон;
- подготавливать данные для КП.

Данные дизайнера должны собираться в КП:

- размеры;
- ткань;
- тюль;
- метраж;
- комнаты;
- окна;
- комментарии.

КП рассчитывает цену, чтобы быстро дать клиенту итоговую стоимость.

Экран дизайнера должен показывать:

- номер заказа;
- клиента;
- дату;
- телефон/адрес, если нужно;
- текущий статус;
- следующий шаг;
- цветной индикатор:
  - новый заказ;
  - в работе;
  - просрочен;
  - требует внимания;
  - готов к КП.

---

## 4. Склад

Склад должен видеть заказы, которые находятся в работе и требуют подготовки материалов.

Склад видит:

- какой заказ в работе;
- какие материалы нужны;
- ткань;
- тюль;
- метраж;
- что нужно собрать;
- что нужно подготовить;
- что нужно передать в цех/швеям.

Основные состояния склада:

- Закупить;
- Нужно сделать;
- Сделано.

Цветной индикатор:

- красный — надо закупить / проблема;
- жёлтый — частично / требует внимания;
- зелёный — готово / сделано.

Склад не должен видеть лишние финансы и админскую аналитику.

---

## 5. Швея / пошив

Швея видит только заказы, которые:

- уже в работе;
- обеспечены материалами полностью или частично;
- готовы к пошиву.

Швея должна видеть прямо в заказе:

- что надо сшить;
- для какой комнаты;
- для какого окна;
- размеры;
- ткань;
- тюль;
- метраж ткани;
- метраж тюля;
- комментарии дизайнера;
- срок.

Все эти данные должны подтягиваться из замера и выбора материалов, которые внёс дизайнер.

Швея не должна видеть:

- цены;
- финансовые данные;
- расчёт КП;
- лишнюю информацию владельца.

Главная задача экрана швеи: открыть список заказов и сразу понять, что шить.

---

## 6. Установщик

Установщик — последняя исполнительная инстанция.

Он видит заказы, которые:

- готовы после пошива;
- готовы к установке/выдаче.

Установщик должен видеть:

- номер заказа;
- клиента;
- телефон;
- адрес;
- дату;
- какие изделия установить;
- для какой комнаты;
- какие позиции/окна;
- статус фотоотчёта;
- статус АВР;
- есть ли остаток оплаты, но без подробных цен.

Установщик может:

- открыть заказ;
- отметить установку/выдачу выполненной;
- сделать фотоотчёт;
- загрузить фото подписанного АВР с телефона;
- напомнить клиенту об остатке оплаты, если он есть.

После выполнения установки, фотоотчёта, АВР и оплаты заказ можно завершить как исполненный.

---

## 7. Финансы

Финансы не должны быть главной производственной ролью на уровне дизайнера, склада, швеи и установщика.

Оплата должна быть видна:

- владельцу на dashboard;
- в заказе;
- в действиях оплаты;
- как предупреждение установщику, если есть остаток.

Исполнители не должны видеть подробные цены, если это не нужно для их роли.

---

## 8. Завершение заказа

Заказ можно завершить только когда выполнены условия:

- установка/выдача завершена;
- фотоотчёт добавлен;
- АВР создан;
- подписанный АВР загружен;
- финальная оплата закрыта.

После этого заказ получает статус completed / завершён.
