# QR-коды для материалов склада — дизайн

Дата: 2026-07-26.

## Проблема

Владелец ателье хочет печатать QR-этикетки на рулоны ткани/тюля и позиции карниза/фурнитуры, чтобы Владелец, Дизайнер и Склад могли отсканировать этикетку в мобильном приложении и сразу увидеть остаток/категорию/цену — без ручного поиска позиции по названию.

## Скоуп

Только материалы (`InventoryItem` — ткань/тюль/карниз/фурнитура/прочее). QR-коды для заказов (сценарии швеи «чей заказ, какая комната» и установщика «заказ, адрес, какое изделие») — сознательно вынесены за скоуп, отдельный проект в будущем.

## Что кодируется в QR

Строка `SHEBER-INV:{id}`, где `{id}` — UUID существующего `InventoryItem`. Не сами данные (остаток, цена) — они постоянно меняются, а печатная этикетка нет. QR — стабильный указатель, при сканировании приложение всегда идёт за актуальными данными в API.

## Печать (веб, экран «Материалы» — `frontend/src/app/work/warehouse/materials/page.tsx`)

- Новый пункт «Печать QR» в существующем меню «⋮» позиции. Виден только при `canEdit` (`role === "owner" || role === "warehouse"`) — том же условии, что уже управляет остальными правами на этом экране.
- Генерация QR — на фронте, библиотека `qrcode` (npm, добавляется в зависимости). Без обращений к бэкенду для генерации самой картинки.
- Открывает окно печати браузера (`window.print()`) с отдельным print-layout: QR-код + под ним название, категория, артикул/SKU. CSS `@media print` подгоняет layout под компактный размер этикетки (примерно 40×30мм) — обычный принтер печатает, дальше вырезается/клеится вручную.
- Вёрстка этикетки — отдельный переиспользуемый компонент (`components/inventory/QrLabel.tsx` или аналог), не завязанный на способ вывода — задел на будущее подключение термопринтера (другой способ вывода того же контента, без изменения логики генерации QR).

## Сканирование (мобильное, экран «Материалы» — `mobile/app/inventory/index.tsx`)

- Новая иконка «Скан» в шапке экрана, рядом с существующими «+» (добавить) и «поиск». Видна всем трём ролям (Owner/Designer/Warehouse) — доступ к самому экрану «Материалы» уже не ограничен по ролям на мобильном уровне (ограничения только на бэкенде, см. ниже).
- Открывает камеру через `expo-camera` (пакет добавляется в зависимости мобилки; входит в состав Expo Go — пересборка приложения не требуется, аналогично `expo-document-picker`/`expo-image-picker`).
- При распознавании QR — парсинг ожидаемого префикса `SHEBER-INV:`. Если строка не соответствует формату — понятная ошибка («Это не QR материала»), не краш.
- По извлечённому `id` — запрос к уже существующему `GET /api/v1/inventory-items/{id}/`.
- Результат показывается в **новом read-only компоненте-карточке** (не в существующей форме `app/inventory/[id].tsx` — та является формой редактирования, а сканирование по всем трём ролям, включая Склад, должно быть просмотром, не правкой, — подтверждено явно в брейншторминге). Карточка: название, артикул, категория, остаток с единицей измерения, цена за единицу.
- Позиция не найдена (404, например — удалена) — отдельное сообщение об ошибке.

## Бэкенд

Изменений не требуется. `InventoryItemViewSet.get_permissions()` уже отдаёт `retrieve` любому аутентифицированному пользователю (`IsAuthenticated()` без дополнительных ограничений по роли) — весь нужный для карточки API уже открыт всем трём ролям.

## Не в этом заходе (сознательно, по итогам брейншторминга)

- Массовая печать этикеток (несколько позиций разом, лист наклеек).
- Термопринтер как таковой — только архитектурный задел (отдельный print-layout компонент), реализация — отдельная задача, когда появится физический принтер.
- QR-коды для заказов/окон замера (сценарии швеи и установщика) — отдельный, более крупный проект: другая модель данных, другие роли доступа.

## Тестирование

- Backend: без изменений, регрессионных тестов не требуется (эндпоинт уже покрыт существующими тестами `InventoryItemViewSet`).
- Frontend: юнит-тест на функцию формирования содержимого QR (`SHEBER-INV:{id}`). Видимость пункта «Печать QR» по роли — ручная проверка в браузере (в проекте нет прецедента рендер-тестов для похожих модалок/экранов — `CreateKPModal`, сам экран «Материалы» — тоже без них; заводить новый паттерн ради одного условия не стали).
- Mobile: юнит-тесты на парсинг/формирование содержимого QR (валидный префикс → id; невалидная строка → null) и на функцию запроса позиции по id. Read-only карточка и сам экран сканирования — презентационные компоненты без прецедента рендер-тестов в мобильном коде (аналогично `InventoryItemForm` и другим), проверяются вручную в Expo Go — сканирование камерой в принципе не покрывается юнит-тестами (аппаратная часть).
