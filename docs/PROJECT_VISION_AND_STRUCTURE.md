# Sheber ERP — Project Vision & Structure

## 1. Vision

Sheber ERP начинается как **MVP для ателье**. Цель — довести систему до рабочего состояния и дать реальным ателье на пилот. Во время пилота собираем данные по заказам, срокам, оплатам, материалам, производству, установке и документам, чтобы валидировать гипотезы и отполировать UX перед масштабированием.

## 2. Guiding Principles

- **Order-first**. Главный объект системы — `Order`. Все сущности (клиент, КП, задачи, материалы, оплаты, документы) вращаются вокруг заказа.
- **Business logic in the backend**. Вся бизнес-логика живёт в backend/service layer. Mobile и web — только thin clients.
- **Mobile = рабочий инструмент**. Мобильное приложение — это инструмент сотрудников в цехе и на установке. Оно должно работать быстро, офлайн- resilient и не требовать обучения.
- **Web = контроль владельца**. Web-админка даёт владельцу ателье видимость по всем заказам, финансам и загрузке персонала.
- **Design via DESIGN_SYSTEM.md**. Визуальный язык системы фиксируется в `DESIGN_SYSTEM.md` и реализуется через `mobile/src/theme` и аналогичные темы в web.
- **No premature universality**. Универсальный продукт для любых производственных нишей не строим сразу. Сначала — глубокая экспертиза в ателье, затем — абстрагирование core-сущностей.

## 3. Core Domain Model

Будущий универсальный core после пилота включает:

| Сущность | Описание |
|----------|----------|
| **Client** | Клиент, замеры, параметры, контакты |
| **Order** | Центральный объект заказа, статус, сроки, сумма |
| **Quote (КП)** | Коммерческое предложение, позиции, согласование |
| **Tasks / Stages** | Этапы производства: дизайн → пошив → установка |
| **Resources / Materials** | Материалы, фурнитура, остатки, списание |
| **Payments** | Оплаты, частичные платежи, задолженность |
| **Documents** | Акты, фотоотчёты, договоры |
| **Users** | Роли, права доступа |
| **Analytics** | KPI по срокам, оплатам, загрузке |

## 4. MVP Boundaries

### In Scope (MVP)
- Создание клиента и фиксация замеров
- Создание КП и согласование с клиентом
- Создание заказа из КП или напрямую
- Статусы заказа и их визуализация
- Этапы производства (Дизайнер → КП → Склад → Пошив → Установка)
- Учёт материалов и готовности
- Частичные оплаты и контроль задолженности
- Мобильное приложение для сотрудников (today, orders, work, detail)
- Web-админка для владельца
- Демо-режим для презентаций

### Out of Scope (MVP)
- Интеграции с бухгалтерией (1С, МойСклад)
- CRM-маркетинг, рассылки, лояльность
- Онлайн-оплата для клиентов
- Многофилиальность
- Подрядчики и внешние исполнители
- AI-прогнозирование сроков (собираем данные, но не строим модель)

## 5. Roles

| Роль | Обязанности | Интерфейс |
|------|-------------|-----------|
| **Владелец / Админ** | Контроль всех заказов, финансы, настройки | Web + Mobile |
| **Дизайнер** | Замеры, эскизы, утверждение КП | Mobile |
| **КП-менеджер** | Составление и согласование КП | Mobile |
| **Склад** | Учёт материалов, резервирование | Mobile |
| **Пошив** | Производственные задачи, фотоотчёты | Mobile |
| **Установка** | Монтажные работы, подписание актов | Mobile |

## 6. Order Status Lifecycle

```
draft → measurements → quote_sent → quote_accepted
        ↓ (прямой заказ)
        order_created → design → warehouse → sewing → installation → done
```

Статусы заказа на русском:
- `draft` — Черновик
- `measurements` — Замеры
- `quote_sent` — КП отправлено
- `quote_accepted` — КП принято
- `order_created` — Заказ создан
- `design` — Дизайн
- `warehouse` — Склад / материалы
- `sewing` — Пошив
- `installation` — Установка
- `done` — Выполнен
- `cancelled` — Отменён

## 7. Roadmap

| Фаза | Цель | Срок |
|------|------|------|
| **Phase 0 — Foundation** | Mobile MVP с demo-данными, responsive UI, status indicators | Done |
| **Phase 1 — Auth & API** | JWT-аутентификация, реальные API endpoints, ролевая модель | Q3 2026 |
| **Phase 2 — Production** | Полный жизненный цикл заказа через backend, push-уведомления | Q4 2026 |
| **Phase 3 — Pilot** | Запуск в 1-2 реальных ателье, сбор обратной связи, доработки | Q1 2027 |
| **Phase 4 — Scale** | Универсальный core, white-label, SaaS-модель | Q2-Q3 2027 |

## 8. Pilot Strategy

1. **Выбор пилотных ателье**. Ищем 1-2 ателье с готовностью к цифровизации и чётким пониманием своих процессов.
2. **Параллельный запуск**. Первые 2-4 недели работают параллельно с текущей системой (Excel/бумага), чтобы не рисковать.
3. **Еженедельные sync-ups**. Созвоны с владельцем и ключевыми сотрудниками для сбора болей.
4. **Метрики пилота**:
   - Среднее время от замеров до готовности
   - % заказов с просрочкой срока
   - % собираемости оплат
   - CSAT сотрудников (оценка удобства приложения)
   - CSAT клиентов (прозрачность сроков)
5. **Go / No-Go**. После 3 месяцев пилота принимаем решение о дальнейшем масштабировании или pivot.

## 9. AI Agent Rules

- **No code without task context**. AI-агенты (Cascade, Copilot и др.) получают контекст через `docs/`, а не через догадки.
- **No backend assumptions**. AI не дорабатывает backend без явного запроса и PR.
- **Preserve demo fallbacks**. В mobile demo-данные — это не «временный костыль», а необходимый fallback для офлайн-режима и презентаций.
- **Theme-first UI changes**. Любые визуальные изменения проходят через существующую тему (`mobile/src/theme/colors.ts`, `spacing.ts`, `typography.ts`, `layout.ts`).
- **No commit without check**. Перед коммитом: typecheck, expo-doctor, git diff review.
- **Explicit boundaries**. AI не решает архитектурные вопросы (переход на другой стек, добавление БД и т.д.) без одобрения.

## 10. Tech Stack

| Layer | Stack |
|-------|-------|
| Backend | Django REST Framework |
| Web Frontend | Next.js + React |
| Mobile | React Native + Expo |
| State | React Query / SWR |
| Auth | JWT (Phase 1) |
| Docs | Markdown in `docs/` |

## 11. File Conventions

- `docs/design/` — дизайн-прототипы, скриншоты Figma
- `docs/design/DESIGN_SYSTEM.md` — единый дизайн-системный документ
- `mobile/src/theme/` — цвета, отступы, типографика, layout
- `mobile/app/` — экраны по file-based routing Expo Router
- `atelier_erp/` — Django backend
- `frontend/` — Next.js web-админка
