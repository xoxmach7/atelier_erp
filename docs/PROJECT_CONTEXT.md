## Проект

Sheber ERP / Atelier ERP — ERP-система для шторного ателье и интерьерного текстиля.

Цель — управлять всем циклом работы ателье: лиды и обращения клиентов; замеры; дизайн; расчёт КП; закуп материалов; производство; монтаж; сдача объекта; финансовая аналитика.

## Основная бизнес-идея

Большинство CRM/ERP не учитывают специфику шторного бизнеса. Работа строится вокруг заказа и его прохождения по этапам:

Обращение клиента → Замер → Подбор тканей → Расчёт стоимости → Согласование КП → Закуп материалов → Производство → Монтаж → Закрытие заказа.

Система должна помогать сотрудникам выполнять свои задачи, а не просто хранить список заказов.

## Главный принцип мобильного приложения

Мобильное приложение НЕ копия веб-панели. Оно для выполнения работы по ролям. Каждый сотрудник видит только те задачи, которые требуют его действий.

## Роли

**Owner / Admin** — видит общую картину, показатели, заказы, сотрудников, финансы. Может: создавать заказы, назначать сотрудников, создавать замеры, создавать и утверждать КП, контролировать процесс.

**Designer / Measurer** — создаёт замеры, заполняет параметры окон, выбирает ткани, создаёт КП на основании замеров. Видит только свои рабочие задачи.

**Warehouse** — видит ТОЛЬКО задачи по материалам (проверить наличие, заказать, материал заканчивается, поставка задерживается, поступил частично). Важно: Warehouse НЕ должен видеть весь заказ — только задачи, связанные с материалами.

**Sewing** — видит только производственные задачи (раскрой, пошив, контроль качества, передача на монтаж).

**Installer** — видит только задачи монтажа (назначенный монтаж, адрес, время, фотоотчёт, акт).

**КП — не отдельная роль**, а часть процесса внутри Owner/Admin и Designer/Measurer.

## Структура мобильного приложения

- **Today** — экран руководителя: прибыль, выручка, расходы, кол-во заказов, просрочки, материалы на исходе. Обзорный.
- **Work** — главный рабочий экран: сотрудник видит ТОЛЬКО свои задачи.
- **Orders** — список заказов для поиска/просмотра. НЕ главный рабочий экран.

## Технический стек (из контекста владельца)

Frontend: React Native, Expo, TypeScript, Expo Router.
Backend (по контексту планировался Laravel + PostgreSQL + REST; по факту реализован на Django + DRF + PostgreSQL).
Авторизация: JWT + RBAC.
Будущее: интеграции WhatsApp/Instagram/Telegram/Email (автосоздание лидов/заказов), автоматизация через n8n.

## Основная философия

Система должна быть максимально простой для сотрудников. Сотрудник не должен думать «где искать работу» — открыл приложение и сразу видит «вот задачи, которые надо сделать сейчас».

## Правила для AI-агентов (из контекста)

- Mobile App = выполнение задач по ролям.
- Orders = список заказов. Today = аналитика владельца.
- Warehouse не должен видеть лишнюю информацию. Sewing — только производство. Installer — только монтаж.
- КП не является отдельной ролью.
- **Простота важнее количества функций.**
- Любая новая функция должна отвечать: «какую конкретную работу сотруднику это помогает выполнить?» Если не помогает — для MVP не нужна.
